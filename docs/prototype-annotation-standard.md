# 高保真原型评审标注标准

> 目标：让 PM 在原型演示中，用业务语言把页面结构、交互、状态、异常和数据讲清楚，尽可能不给下游留下需要猜测的信息缺口。

## 1. 标注的定位

标注是**评审与演示层**，不是最终产品界面的一部分，也不是技术设计文档。它回答：

- 谁在什么场景下使用本页？目标和完成结果是什么？
- 页面由哪些区域组成，每个区域为什么存在？
- 用户怎么操作，系统如何反馈，遵循什么业务规则？
- 页面有哪些状态，分别何时出现、数据是什么、能做什么？
- 异常为什么发生，用户看到什么，如何继续或恢复？
- 数据从哪来，允许值、空值和校验规则是什么？

技术架构、接口、数据库、框架和状态码留在技术文档。标注中统一说用户行为、可见反馈和业务结果。

## 2. 每页必须交付的说明

| 模块 | 必须回答 |
|---|---|
| `overview` | 角色、场景、目标、入口、完成结果、当前状态、所属流程 |
| `sections` | 区域名称、区域作用、包含内容、对应页面元素 |
| `interactions` | 操作名称、触发方式、系统反馈、业务规则、后续去向 |
| `states` | 状态触发、数据状态、可见/可用行为、恢复路径、对应原型页 |
| `exceptions` | 异常名称、触发原因、用户反馈、恢复路径、对应元素 |
| `data` | 数据名称、业务含义、允许值/状态、为空行为、校验、来源 |

纯数据无关页可以使用 `data_not_applicable`，但必须写出业务理由。

## 3. 状态必须逐项枚举

以下五类状态在每个页面族中都必须出现：

| 状态 | 必须讲清 |
|---|---|
| `default` | 用户刚进入时看到什么，哪些功能可用 |
| `loading` | 正在处理什么，是否允许重复操作，如何取消或等待 |
| `empty` | 为什么没有数据，当前数据形态，下一步怎么继续 |
| `success` | 成功结果是什么，用户能完成什么后续动作 |
| `error` | 失败原因、是否保留用户输入、如何重试或求助 |

用户可达时还要增加：禁用、无权限、离线、部分数据、过期数据、编辑中、冲突、超限等状态。不能为了通过校验而省略真实场景。

确实不适用时，使用：

```yaml
- kind: empty
  not_applicable: true
  reason: "本页是单条记录详情，不存在列表为空的情况；记录不存在由 error 状态覆盖"
```

“懒得写”“没有设计”“后续再说”不是有效理由。

## 4. 好标注与坏标注

### 坏标注

> 搜索框，支持搜索。

问题：没有角色、输入规则、反馈、空值、失败、恢复，也没有业务目标。

### 好标注

- **操作**：点击输入框并输入希望查找的内容。
- **输入规则**：去除首尾空格，允许 1–100 个字符；为空时搜索按钮不可用。
- **系统反馈**：有效关键词使搜索按钮可用；提交后保留关键词并显示搜索中状态。
- **无结果**：说明没有符合权限和关键词的内容，可修改关键词或清除筛选。
- **失败**：暂时无法验证权限时，不展示未鉴权内容；用户可重试，连续失败联系知识管理员。

### 技术化表达（禁止）

> API 返回 HTTP 500，JSON 解析失败。

### 业务化表达

> 搜索服务暂时不可用，已输入的关键词仍然保留；点击重试，连续失败时联系知识管理员。

## 5. 评审演示方式

1. 点击页面中的数字角标，打开该元素的详细说明。
2. 点击“演示”，从第一条开始，用上一条/下一条逐项讲解；当前元素同步高亮。
3. 使用四个分类页签：
   - **页面结构**：目标、入口、完成结果和区域职责。
   - **交互**：操作、反馈、规则和去向。
   - **状态与异常**：完整状态目录、异常和恢复路径。
   - **数据**：业务含义、允许值、空值、校验和来源。
4. 状态说明中的“查看此状态页面”用于切换对应原型状态。
5. 团队评审时按“目标 → 主流程 → 各状态 → 异常恢复 → 数据规则”顺序验收，不只检查默认页面。

## 6. 自动校验

```bash
python scripts/lincoln_prototype_annotations.py issue-<N>
```

core-v2 以下情况不能通过：

- 缺少 `annotations` 或任一必需模块。
- 标注目标不存在，或说明只有空泛一句话。
- 五类基础状态缺项，或不适用没有业务理由。
- 异常缺触发、用户反馈或恢复路径。
- 当前状态未登记，状态链接指向不存在页面。
- 数据规则缺失，或叙述包含实现术语。
- 同一状态重复定义。

旧版只有 `hotspots` 的工作包继续按 legacy 模式运行，不强制回填；新 core-v2 原型必须满足完整标注契约。
